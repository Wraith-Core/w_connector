# w_connector (v2)

يربط سيرفر FiveM أو RedM بلوحة Wraith، وينفذ أوامر الإدارة ويعرض حالة اللاعبين.
تتوفر لوحة w_admin الأصلية داخل الموصل بالأمر `/wadmin` أو F10، وقائمتها السريعة بـPage Up أو `/wquickadmin` في RedM وFiveM.
تظهر الصفحات والأفعال حسب صلاحيات حساب الموقع. إدارة الرتب المفوّضة متاحة من داخل اللعبة لمن لديه صلاحية إدارة الرتب.
توجد أيضًا أوامر البلاغات بحسب الإعدادات. يتطلب المورد `oxmysql` وإطارًا مدعومًا.

> This is v2, shipped under the name `w_connector` so the Wraith systems (which answer only that
> name) work unchanged. It replaces v1, whose source is kept in `game/w_connector_v1` for rollback:
> put the v1 folder back and start it. Design: `docs/admin-platform/03-connector-v2.md`.

## Install

1. Requirements: `oxmysql`, and one supported framework.
2. Put `w_connector` in `resources/`.
3. On your panel, create the connector token, then add to `server.cfg`:

```cfg
set wraith_token "wc2.k…"
ensure w_connector
add_ace resource.w_connector command allow
```

Start it **after** your framework and inventory.

## Supported

| Framework | Inventory |
|---|---|
| Wraith Core (`w_core`) | Wraith (`w_inventory`) |
| VORP (`vorp_core`) | `vorp_inventory`, `ox_inventory` (RedM) |
| RSG (`rsg-core`) | `rsg-inventory` |
| ESX (`es_extended`) | `ox_inventory`, or ESX's own |
| QBCore (`qb-core`) | `qb-inventory` |
| Qbox (`qbx_core`) | `ox_inventory` |

Detected automatically. To force one: `set wraith_framework "vorp"` / `set wraith_inventory "ox_inventory"`.

## Security

- The token belongs to this one server and this one product. Keep `server.cfg` private; if it leaks,
  create a new token on the panel — the old one stops working.
- Every request is signed (HMAC-SHA256, timestamp and one-time nonce) and goes out over HTTPS. The
  server opens no port.
- The token cannot change who has access to your panel.

## 2.4.0 — 2026-11-03

- صفحة جديدة في لوحة الإدارة (Page Up) ← «العالم» ← «العلامات»: علامات على خريطة اللعبة الأصلية يراها كل اللاعبين في الخريطة وعلى الرادار. تضيف علامة باسم وشكل من أشكال اللعبة نفسها (627 شكلًا مع صورها من ملفات اللعبة، نفس قائمة w_map، وبحث بالاسم) ولون من ألوان اللعبة الـ32 أو بدون لون، وحجم، ومكان بالأرقام أو «موقعي الآن» أو «نقطة الطريق». وتعدّلها وتحذفها (مع تأكيد) وتنتقل إليها.
- الصفحة تعمل فقط إذا كان سكربت الخريطة w_map متوقفًا. إذا كان w_map يعمل تختفي الصفحة من القائمة ومن البحث (Ctrl+K)، ويُرفض أي طلب لها برسالة أن العلامات تُدار من محرر w_map بالأمر /mapedit، وتُزال علاماتنا من خرائط اللاعبين حتى لا تتكرر مع علاماته. إذا أوقفت w_map ترجع الصفحة والعلامات خلال ثانية تقريبًا، بدون إعادة تشغيل.
- الصلاحية من الموقع: «التحكم بالطقس والوقت» (world.control)، نفس صلاحية علامات الخريطة في الموقع. كل حفظ وحذف يُسجَّل في سجل الموقع. الانتقال إلى العلامة يحتاج صلاحية الانتقال كما في «أدواتي».
- العلامات محفوظة في السيرفر نفسه (KVP للموصل) وتبقى بعد إعادة التشغيل والتحديث، وتصل لكل لاعب عند دخوله وعند أي تغيير. الحد 200 علامة، والاسم 48 حرفًا.
- يحتاج تحديث الموقع ليقبل الأفعال الجديدة (blips.list / blips.save / blips.delete)؛ قبل تحديثه لا تظهر الصفحة.
- التجربة المطلوبة في اللعبة: أوقف w_map (stop w_map) ثم افتح اللوحة ← «العالم» ← «العلامات». أضف علامة بـ«موقعي الآن» وشكل shop store ولون أخضر، وافتح خريطة اللعبة وتأكد أنها ظهرت باسمها ولونها، وأن لاعبًا آخر يراها. عدّل الاسم والحجم واللون وتأكد أن الخريطة تغيّرت، ثم «انتقل إليها» ثم احذفها. ضع نقطة طريق وجرّب «نقطة الطريق». بعدها شغّل w_map (start w_map) واللوحة مفتوحة: يجب أن تختفي الصفحة خلال ثانية وتختفي علاماتنا من الخريطة، وتظهر من جديد إذا أوقفته. أعد تشغيل السيرفر وتأكد أن العلامات باقية.

- طريقة الدخول مثل txAdmin، وتُضبط من تبويب «الدخول» في لوحة الموقع: مفتوح للجميع، الإدارة فقط (صيانة)، أعضاء سيرفر الديسكورد، رتب ديسكورد محددة، أو بموافقة الإدارة. كل رفض يظهر للاعب بالعربي مع سببه، ومع «تعليمات الدخول» التي تكتبها في اللوحة، وفي وضع الموافقة مع رقم طلبه (مثل R1234) ليعطيه للإدارة.
- إذا لم يصل السيرفر إلى الموقع يبقى كما كان: يدخل اللاعبون (إلا إذا كان `wraith_join_fail_closed` مفعّلًا)، والمحظورون والإغلاق محفوظان محليًا.
- إصلاح صلاحيات السكربتات من الموقع: كانت لا تصل للاعب أبدًا، وكان السيرفر يكتب كل 15 ثانية «native permission cleanup is pending». السبب أن السيرفر يرد على الأمر دائمًا بـ false ويرد على فحص الصلاحية بالرقم 1، فكان الموصل يظن أن كل خطوة فشلت. الآن يتحقق من الصلاحية نفسها فقط، وتُمسح السجلات العالقة القديمة عند التشغيل. لم يحصل أي لاعب على صلاحية بالخطأ.
- تجربة صلاحيات السكربتات: أعط لاعبًا تجريبيًا صلاحية سكربت واحد من الموقع وتأكد أنها تعمل خلال 15 ثانية، ثم اسحبها وتأكد أنها توقفت، ثم اخرج وادخل. يجب ألا تظهر رسالة «cleanup is pending» في الكونسول.
- تجربة اللعبة المطلوبة: اختر في اللوحة «بموافقة الإدارة» وادخل بحساب غير موافق عليه (تظهر رسالة برقم الطلب)، اقبل الطلب من «طلبات الدخول» ثم ادخل مرة ثانية. جرّب «الإدارة فقط» بحساب بلا رتبة في اللوحة، و«أعضاء سيرفر الديسكورد» بحساب خارج سيرفر الديسكورد، وأغلق ديسكورد على الكمبيوتر لترى رسالة «اربط ديسكورد مع ريد إم».

## 2.2.2 — 2026-11-01

- إذا كان w_admin شغالًا تبقى أوامره هو، ولا يتكرر أمر.
- تجربة اللعبة المطلوبة: أوقف w_admin، ثم جرّب /admin و/noclip مرتين و/announce 30s تجربة و/warn على لاعب تجريبي و/staffchat و/vector4، وتأكد أن لاعبًا بلا رتبة في الموقع يرى سبب الرفض.
